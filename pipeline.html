NYC Taxi Trip Duration — Complete MLOps Pipeline

Setup A: Train locally with MLflow tracking. GitHub Actions runs tests + automates deployment after you manually approve.

💻 Your Laptop — where you develop, train, and experiment
1

Data Ingestion

wget / urllib

Download latest month's Parquet file from NYC TLC website. Save to data/bronze/ untouched. New file appears every month at a predictable URL — no API key needed.

2

Data Validation

Pandera

Schema checks: are columns present and typed correctly? Range checks: no negative fares, no trips to the moon (max distance 307K miles in your data!), no dates from 2008. If validation fails → pipeline stops. Never train on bad data.

3

Data Cleaning

pandas

Filter garbage rows (negative fares, 0-second trips, 24hr+ trips). Fill nulls in passenger_count. Compute target: trip_duration_minutes = (dropoff - pickup) / 60. Output → data/silver/

4

Feature Engineering + Split

pandas DVC

Extract: hour, day_of_week, is_weekend, is_rush_hour, is_airport. Keep: PULocationID, DOLocationID, trip_distance. Split into train (90%) + frozen test (10%). Version with DVC (backed by Google Drive). Output → data/gold/

5

Training (Config Sweep)

LightGBM MLflow Tracking

Train 3-5 LightGBM configs with different hyperparameters. Each run logs params, metrics (RMSE, MAE, R²), and model artifact to local MLflow (SQLite). All runs visible at localhost:5000.

6

👁️ YOU: Compare & Pick Winner

MLflow UI

Open mlflow ui → localhost:5000. Visually compare all training runs. Sort by val_rmse. Pick the best one. This is the manual verification step — you decide which model is good enough.

7

Evaluation Gate

evaluate.py

Run best model against frozen test set. If RMSE < 5.0 minutes → PASS. If RMSE ≥ 5.0 → FAIL, model is rejected. This prevents bad models from ever being deployed.

8

Register Model

MLflow Registry

Register the passing model in MLflow: taxi-duration-predictor v1 → Production. Export model artifact to model_artifact/ folder for Docker packaging.

⬇ YOU: git push (triggers automation)
⚙️ GitHub Actions — automated CI + deployment (runs on GitHub's free servers)
9

CI: Run Tests

pytest ci.yml

On every git push: install deps → run pytest tests/ (unit tests for cleaning, validation, feature engineering). Catches bugs before they reach production. No training happens here.

10

CD: Build & Push Docker Image

Docker deploy.yml

If tests pass AND you pushed to main branch: build Dockerfile.serve (with model baked in) → push image to Docker Hub → trigger Render redeploy via webhook. Fully automated after your git push.

⬇ Automatic deploy
🌐 Render.com (Free Tier) — always-on prediction server, accessible to anyone on the internet
11

Live API Server (24/7)

FastAPI uvicorn

Runs your Docker image. Serves predictions at https://taxi-predictor.onrender.com/predict. Send pickup/dropoff zones + time → get predicted trip duration in minutes. This URL goes on your resume.

🔄 The Monthly Development Loop

This is what you do every month when new taxi data drops. Everything runs on your laptop.

1

Download new month's data

python src/ingest.py --year 2026 --month 6
2

Validate the new data

python src/validate.py

If this fails, STOP. Investigate why the data looks different this month.

3

Clean + Engineer features + Split

python src/clean.py && python src/features.py && python src/split.py
4

Train multiple configs

python src/train.py

Sweeps 3-5 LightGBM hyperparameter configs. Each logged to MLflow.

5

👁️ Review in MLflow UI

mlflow ui → open localhost:5000

Compare runs. Sort by RMSE. Pick the winner. This is YOUR judgment call.

6

Evaluate + Register

python src/evaluate.py --run-id <best> && python src/register.py --run-id <best>

Gate check on frozen test set. If passes → register in MLflow as Production.

7

Deploy: git push → automated from here

git add . && git commit -m "retrain on June 2026 data" && git push

GitHub Actions runs tests → builds Docker image → pushes to Render. Done!

🚀 The Deployment Flow (What Happens After git push)

After you train locally, verify in MLflow, and push to GitHub — everything below is fully automatic.

A

You push to GitHub

Your commit includes: updated source code + the exported model artifact in model_artifact/

B

GitHub Actions: ci.yml triggers

Installs dependencies → runs pytest tests/ → validates data schemas. If any test fails → deployment is blocked.

C

GitHub Actions: deploy.yml triggers

Builds Dockerfile.serve (FastAPI + model baked in) → pushes image to Docker Hub → calls Render's deploy webhook.

D

Render pulls new image & restarts

Old container shuts down → new container with new model starts up → https://taxi-predictor.onrender.com/predict now serves the updated model. Zero downtime if configured correctly.
